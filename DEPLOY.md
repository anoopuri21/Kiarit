# Deploying KIARIT to Cloudflare

The site deploys straight from GitHub. You push a change, Cloudflare notices,
builds it, and puts it live. **You never run anything on your own computer.**

The site will go live on a free Cloudflare address that looks like:

```
https://kiarit.<your-account-name>.workers.dev
```

You do not need to buy a domain for this. Part 4 covers attaching a real
domain later.

---

## Part 1 — Merge the code into `main` (once, ~1 minute)

Cloudflare deploys whatever is on the repository's **production branch**,
which is `main`. Right now `main` only contains a README — the actual website
is on a working branch, waiting in a pull request.

1. Open <https://github.com/anoopuri21/Kiarit/pull/1>
2. Click the green **Merge pull request** button.
3. Click **Confirm merge**.

`main` now contains the website. Nothing is live yet.

---

## Part 2 — Create the Worker from GitHub (once, ~3 minutes)

4. Go to <https://dash.cloudflare.com> and log in.
5. In the left sidebar click **Workers & Pages**.
6. Click the blue **Create application** button.
7. Find **Import a repository** and click **Get started** next to it.
8. Cloudflare shows your GitHub account and its repositories. Click
   **Kiarit** in the list.
9. You now get a settings screen. Set these **three** fields:

   | Field | What to enter |
   |---|---|
   | **Project name** | `kiarit` |
   | **Build command** | `python3 tools/build_dist.py` |
   | **Deploy command** | `npx wrangler deploy` |

   Leave everything else exactly as it is. If a "Build output directory" box
   appears, leave it blank — `wrangler.jsonc` already specifies it.

10. Click **Save and Deploy**.

Cloudflare now downloads your code, runs the build, and publishes it. This
takes roughly one to two minutes the first time. You will see the log
scrolling; wait for **Success**.

11. When it finishes, Cloudflare shows your live address, ending in
    `.workers.dev`. **Click it.** Your site is on the internet.

---

## Part 3 — Making changes from now on

This is the part that matters day to day. There is no deploy step at all.

12. Edit a file on GitHub (open the file, click the pencil icon, make the
    change, click **Commit changes**).
13. That is it. Cloudflare sees the commit and redeploys within about a
    minute.

To watch it happen: **Workers & Pages** → **kiarit** → **Deployments**. Each
push appears as a new entry with a build log.

### Which files to edit

Most pages are **generated by scripts** — editing them directly gets your
change wiped on the next build. The safe rule:

| To change | Edit |
|---|---|
| The home page | `index.html` — hand-written, edit freely |
| Header or footer, any page | `tools/partials/header.html`, `tools/partials/footer.html` |
| Product names, prices, sizes | `tools/build.py` (the `PRODUCTS` list near the top) |
| About / Contact / Order text | `tools/pages_phase4.py` |
| Products or a product page | `tools/pages_phase5.py` |
| Policy pages | `tools/pages_phase6.py` |
| Images | Upload into `assets/img/`, keeping the same filename to replace one |

If you edit any `tools/` file, the generated HTML must be rebuilt. Tell me and
I will rebuild and push, or run the three generator scripts yourself. **Do not
hand-edit `about.html`, `products.html`, `product-1.html` and so on** — those
are outputs, not sources.

### Undoing a bad deploy

**Workers & Pages** → **kiarit** → **Deployments**. Every past version is
listed. Open a previous one and choose **Rollback**. This is instant and does
not touch GitHub.

## Part 4 — Attaching your real domain (when you buy one)

Do this only once you own `kiaritpharmaceuticals.com`.

14. In the Cloudflare dashboard click **Add a domain**, type your domain, and
    choose the **Free** plan.
15. Cloudflare shows you **two nameservers**, e.g. `dana.ns.cloudflare.com`.
16. Log in wherever you bought the domain (GoDaddy, Namecheap, BigRock…), find
    the **Nameservers** setting, delete what is there, paste Cloudflare's two
    values in, and save.
17. Wait. Anywhere from 10 minutes to 24 hours. Cloudflare emails you when the
    domain is active.
18. Once active: **Workers & Pages** → **kiarit** → **Settings** →
    **Domains & Routes** → **Add** → **Custom domain** →
    type `www.kiaritpharmaceuticals.com` → confirm.

The HTTPS certificate is issued automatically and free. Nothing to install or
renew.

19. **One code change will be needed.** The site currently tells search engines
    its address is `https://www.kiaritpharmaceuticals.com`. If your real
    domain differs even slightly, tell me and I will update it — otherwise
    Google indexes the wrong address.

### Recommended settings once the domain is attached

- **SSL/TLS → Overview** → **Full (strict)**.
- **SSL/TLS → Edge Certificates** → turn on **Always Use HTTPS**.
- **Speed → Optimization → Image Optimization** → turn on **Polish**, set
  **Lossy**, tick **WebP**. Cuts roughly 500 KB off the product photography
  with no code change.

## Reference

### What the build actually does

`python3 tools/build_dist.py` copies the real website files — HTML, images,
CSS, fonts — into a `dist/` folder. It deliberately excludes things the public
must never see, such as the `tools/` scripts and the `.git` history, and it
**stops with an error** if anything unexpected would be published. Cloudflare
then uploads that folder to servers in hundreds of cities, so a visitor in
Delhi is served from Delhi.

### Configuration files

| File | What it does |
|---|---|
| `wrangler.jsonc` | Names the project and points Cloudflare at `dist/`. |
| `_headers` | Security headers and caching rules. |
| `_redirects` | Old `.html` addresses → clean ones, plus aliases like `/shop`. |
| `package.json` | Pins wrangler so builds are repeatable. |
| `.python-version`, `.nvmrc` | Pin the language versions Cloudflare builds with. |
| `.htaccess` | **Ignored by Cloudflare.** Kept only for possible shared hosting. |

### Addresses

Pages use clean addresses — `/about`, not `/about.html`. Old `.html` addresses
permanently redirect (a "301") to the clean version, so previously shared links
keep working and search engines carry the ranking across.

### Caching

Images, CSS, fonts and JavaScript are cached in visitors' browsers for a year.
HTML pages are never cached, so edits appear as soon as the deploy finishes.
You should not need to clear any cache.

### Cost

Static files with no server-side code, so Cloudflare serves it without running
anything billable. The free tier covers this comfortably.

## If something goes wrong

**Build failed: `python3: command not found`** — the Build command is wrong.
Check it is exactly `python3 tools/build_dist.py` under **Settings → Build**.

**Build failed: "directory specified by assets.directory does not exist"** —
the build command did not run or failed earlier. Read the log above that line
for the real error.

**Build succeeded but the site looks unchanged** — hard-refresh with
`Ctrl+Shift+R` (Windows) or `Cmd+Shift+R` (Mac).

**A page reverted after you edited it** — you edited a generated file. See the
table in Part 3 and edit the `tools/` source instead.

**Cloudflare is not building on push** — confirm you pushed to `main`.
Builds only trigger on the production branch.
